================================================================================
                              1. STRING
================================================================================

DEFINITION:
-----------
String is a sequence of characters.

Example:

    "Hello"
    "Java"
    "Divyansh"


In Java:

    String is a CLASS.

It is NOT a primitive data type.


Example:

    String name = "Divyansh";


String belongs to:

    java.lang.String


Therefore, we do NOT need to import it.

================================================================================
                     STRING DECLARATION
================================================================================

Example:

    String str;


Here:

    str

is a reference variable.

No String object has been explicitly created yet.


We can create a String using:

    String str = "Hello";


or:

    String str = new String("Hello");


Both are valid, but they behave differently in terms of
object creation and the String Pool.


================================================================================
                       STRING LITERAL
================================================================================

Example:

    String s = "Hello";


"Hello" is called a:

    STRING LITERAL


String literals are handled specially by Java using the:

    STRING CONSTANT POOL

also called:

    STRING POOL


================================================================================
                         STRING POOL
================================================================================

String Pool is a special area associated with the JVM heap where
Java can store and reuse String literals.

Example:

    String a = "Hello";
    String b = "Hello";


Java can reuse the same pooled String object for both references.

Conceptually:

                 String Pool
                +-----------+
                |  "Hello"  |
                +-----------+
                  ↑       ↑
                  |       |
                  a       b


Therefore:

    a == b

can be:

    true


because both references can point to the same pooled object.


IMPORTANT:
----------
This does NOT mean we should compare String contents using ==.


For content comparison, use:

    equals()


Example:

    a.equals(b)


================================================================================
                    STRING USING new KEYWORD
================================================================================

Example:

    String a = new String("Hello");
    String b = new String("Hello");


Here, each new String explicitly creates a separate String object.

Conceptually:

    a ---> "Hello"

    b ---> "Hello"


The objects are different.


Therefore:

    a == b

returns:

    false


But:

    a.equals(b)

returns:

    true


because their CONTENT is the same.


================================================================================
                         == VS equals()
================================================================================

This is one of the MOST IMPORTANT String concepts.


==

Checks:

    REFERENCE / OBJECT IDENTITY


equals()

Checks:

    CONTENT / VALUE


Example:

    String a = new String("Java");
    String b = new String("Java");


    a == b

    false


    a.equals(b)

    true


🔥 MEMORY TRICK:

    ==       -> "Are they the SAME OBJECT?"
    equals() -> "Do they have the SAME CONTENT?"


================================================================================
                         STRING IMMUTABILITY
================================================================================

String is:

    IMMUTABLE


Immutable means:

    Once a String object is created, its content cannot be changed.


Example:

    String s = "Hello";

    s = s + " World";


It may look like the existing String was modified.

But actually:

    "Hello"

was NOT modified.


A new String:

    "Hello World"

is created.


Then:

    s

is made to refer to the new String.


Conceptually:

Before:

    s
    |
    v
    "Hello"


After:

    s
    |
    v
    "Hello World"


The original "Hello" object remains unchanged.


================================================================================
                    WHY IS STRING IMMUTABLE?
================================================================================

String immutability provides several benefits:

1. SECURITY
-----------

Strings are used for:

    passwords
    file paths
    URLs
    database connections
    class names


If Strings could change unexpectedly, security problems could occur.


2. STRING POOL
--------------

Because Strings are immutable, Java can safely reuse String objects
from the String Pool.


3. THREAD SAFETY
----------------

Immutable objects can safely be shared between threads because
their state cannot be changed.


4. HASHING
----------

Strings are commonly used as keys in:

    HashMap
    HashSet


Immutability ensures their hash value/content does not unexpectedly change.

                         equals()

================================================================================
                          compareTo()
================================================================================

compareTo() compares Strings lexicographically.

Lexicographical means dictionary-like ordering based on characters.


Example:

    "apple".compareTo("banana")


Result:

    negative value


Because:

    apple < banana


If:

    a.compareTo(b) == 0

Then both Strings are equal in lexicographical ordering.


If:

    a.compareTo(b) < 0

Then:

    a comes before b.


If:

    a.compareTo(b) > 0

Then:

    a comes after b.


IMPORTANT:
----------
Do NOT memorize the exact non-zero number.

Remember:

    negative -> smaller
    zero     -> equal
    positive -> greater


================================================================================
                     compareToIgnoreCase()
================================================================================

Same concept as compareTo(),

but ignores case differences.


Example:

    "java".compareToIgnoreCase("JAVA")


Returns:

    0

================================================================================
                     2. STRINGBUILDER
================================================================================

DEFINITION:
-----------
StringBuilder is a mutable sequence of characters.

Unlike String:

    String       -> Immutable
    StringBuilder -> Mutable


Package:

    java.lang.StringBuilder


No import is required.


Example:

    StringBuilder sb = new StringBuilder();


================================================================================
                       WHY STRINGBUILDER?
================================================================================

Suppose:

    String s = "";

    for(int i = 0; i < 1000; i++) {
        s = s + i;
    }


Because String is immutable, many intermediate String objects
may be created.


StringBuilder is designed for repeated modifications.


Example:

    StringBuilder sb = new StringBuilder();

    for(int i = 0; i < 1000; i++) {
        sb.append(i);
    }


This is generally much more efficient for repeated concatenation.


================================================================================
                          append()
================================================================================

Adds data at the end.


Example:

    StringBuilder sb = new StringBuilder("Hello");

    sb.append(" Java");


Result:

    "Hello Java"


Can append many types:

    sb.append(10);
    sb.append(10.5);
    sb.append(true);
    sb.append('A');


================================================================================
                          insert()
================================================================================

Inserts data at a specified index.


Example:

    StringBuilder sb = new StringBuilder("Hello");

    sb.insert(5, " Java");


Result:

    "Hello Java"


Example:

    StringBuilder sb = new StringBuilder("Helo");

    sb.insert(2, "l");


Result:

    "Hello"


================================================================================
                          delete()
================================================================================

Deletes characters from:

    start index

to:

    end index


Example:

    StringBuilder sb = new StringBuilder("Hello World");

    sb.delete(5, 11);


Result:

    "Hello"


IMPORTANT:
----------
Like substring():

    start -> INCLUDED
    end   -> EXCLUDED


🔥 MEMORY TRICK:

    delete(start, end)
    = [start, end)


================================================================================
                         deleteCharAt()
================================================================================

Deletes one character.


Example:

    StringBuilder sb = new StringBuilder("Hello");

    sb.deleteCharAt(1);


Result:

    "Helo"


================================================================================
                            setCharAt()
================================================================================

Changes the character at a specific index.


Example:

    StringBuilder sb = new StringBuilder("Java");

    sb.setCharAt(0, 'K');


Result:

    "Kava"


IMPORTANT:
----------
This demonstrates mutability.

String cannot directly do:

    str.setCharAt(...)


StringBuilder can.


================================================================================
                            charAt()
================================================================================

Returns character at index.


Example:

    StringBuilder sb = new StringBuilder("Java");

    sb.charAt(2);


Result:

    'v'


Same concept as String.


================================================================================
                            reverse()
================================================================================

Reverses the sequence.


Example:

    StringBuilder sb = new StringBuilder("Java");

    "avaJ"


VERY IMPORTANT FOR DSA.

    String s = "hello";

================================================================================
                            length()
================================================================================

Returns number of characters.


Example:

    StringBuilder sb = new StringBuilder("Hello");

    sb.length();


Result:

    5


================================================================================
                          capacity()
================================================================================

Returns the current capacity of the StringBuilder.


Example:

    StringBuilder sb = new StringBuilder();

    System.out.println(sb.capacity());


The default initial capacity in standard Java implementations is
16 characters.


If we create:

    StringBuilder sb = new StringBuilder(50);


Initial capacity is:

    50


IMPORTANT:
----------
Capacity != Length


Example:

    StringBuilder sb = new StringBuilder(50);

    sb.append("Hello");


Then:

    length   = 5
    capacity = 50


Capacity means approximately how many characters can be stored before
another expansion is required.


================================================================================
                          ensureCapacity()
================================================================================

Ensures that the builder has at least the specified capacity.


Example:

    sb.ensureCapacity(100);


This can be useful when we know a large amount of data will be appended.


================================================================================
                          setLength()
================================================================================

Changes the length of the StringBuilder.


Example:

    StringBuilder sb = new StringBuilder("Hello");

    sb.setLength(3);


Result:

    "Hel"


If the new length is greater than the current length, the builder is
extended with null characters.

Example:

    "Hello"


VERY IMPORTANT:

    sb.toString()

================================================================================
                  STRING VS STRINGBUILDER
================================================================================

String:

    Immutable


StringBuilder:

    Mutable


String:

    Every modification creates/returns a new String.


StringBuilder:

    Modifies the same builder object.


String:

    Good when content does not need repeated modification.


StringBuilder:

    Good for frequent modifications.


String:

    Thread-safe due to immutability for shared state.


StringBuilder:

    Not synchronized.


For synchronized mutable character sequences:

    StringBuffer


================================================================================
                  STRING VS STRINGBUILDER EXAMPLE
================================================================================

STRING:

    String s = "Hello";

    s = s + " Java";


Original:

    "Hello"

remains unchanged.

A new String is produced.


STRINGBUILDER:

    StringBuilder sb = new StringBuilder("Hello");

    sb.append(" Java");


The same StringBuilder object is modified.


================================================================================
                   STRINGBUILDER VS STRINGBUFFER
================================================================================

StringBuilder:
    Mutable
    Not synchronized
    Generally faster
    Preferred in single-threaded code


StringBuffer:
    Mutable
    Synchronized
    Thread-safe methods
    Usually slower because of synchronization


MEMORY TRICK:

    String        -> Immutable
    StringBuilder -> Mutable + Faster
    StringBuffer  -> Mutable + Synchronized


================================================================================
                     STRING CONCATENATION IN DSA
================================================================================

Suppose:

    String result = "";

    for(int i = 0; i < n; i++) {
        result += i;
    }


Repeated String concatenation can be inefficient because Strings are immutable.


Better:

    StringBuilder result = new StringBuilder();

    for(int i = 0; i < n; i++) {
        result.append(i);
    }


Finally:

    result.toString();


🔥 DSA RULE:

    Frequent String modification
            ↓
      StringBuilder


================================================================================
                       PALINDROME USING STRING
================================================================================

A palindrome reads the same forward and backward.


Example:

    "madam"

Reverse:

    "madam"


Therefore it is a palindrome.


Using StringBuilder:

    String s = "madam";

    String reverse =
            new StringBuilder(s)
                    .reverse()
                    .toString();

    if(s.equals(reverse)) {
        System.out.println("Palindrome");
    }


================================================================================
                    STRINGBUILDER FOR REVERSAL
================================================================================

Example:

    String s = "hello";

    StringBuilder sb = new StringBuilder(s);

    sb.reverse();

    System.out.println(sb);


Output:

    olleh


IMPORTANT:

    reverse()

modifies the StringBuilder itself.

================================================================================
                   CHARACTER FREQUENCY PATTERN
================================================================================

Example:

    String s = "banana";

    int[] freq = new int[26];

    for(char ch : s.toCharArray()) {

        freq[ch - 'a']++;
    }


Why:

    'a' - 'a' = 0
    'b' - 'a' = 1
    'c' - 'a' = 2

and so on.


This is extremely important for:

    Anagrams
    Frequency counting
    Duplicate characters
    Character comparison

================================================================================
                         STRING TIME COMPLEXITY
================================================================================

Important:

String operation complexity depends on the operation and implementation.

Common practical expectations:

length():
    O(1)


charAt():
    O(1)


equals():
    O(n) worst case


compareTo():
    O(n) worst case


indexOf():
    O(n) for simple cases, with behavior depending on implementation
    and searched sequence.


substring():
    Modern Java creates an appropriate String representation/copy,
    so do not assume old Java's historical shared-character-array behavior.


toCharArray():
    O(n)


toLowerCase()/toUpperCase():
    Generally O(n), with Unicode/casing details depending on content.


trim()/strip():
    Generally O(n)


split():
    O(n) or more depending on regex complexity and number of pieces.


concat():
    Generally O(n + m) for resulting content.


IMPORTANT:
----------
Always consider the amount of data that must be processed/copied.

    s.toUpperCase();

    s = s.toUpperCase();

    sb.length()

    true

    false

    true

Example:

    String a = new String("Java");

Then:

    b == "Java"

    true
