/*
================================================================================
1. DATA STRUCTURE
================================================================================

Data Structure = A way of organizing and storing data so that we can
efficiently access, modify, insert, delete, or process that data.

Examples:

    Array
    ArrayList
    LinkedList
    Stack
    Queue
    Set
    Map
    Tree
    Graph

Different data structures organize data differently.

One important property we can observe is:

                "Is the order of elements maintained?"
                           /              \
                         YES              NO
                          |                |
                     List / Queue       Set / Map
================================================================================

/*
================================================================================
2. ORDER MAINTAINED VS ORDER NOT MAINTAINED
================================================================================

Suppose we insert:

    10
    20
    30
    40

If a data structure maintains insertion order:

    10 → 20 → 30 → 40

Then we call it ORDER MAINTAINED.

If the data structure does not guarantee insertion order:

    30 → 10 → 40 → 20

then we call it NOT ORDER MAINTAINED.

IMPORTANT:

"Order maintained" does NOT necessarily mean:

    index based

These are two different concepts.

Example:

ArrayList:
    - maintains insertion order
    - index based
    - random access

LinkedList:
    - maintains insertion order
    - NOT efficiently index based
    - sequential access

Set:
    - depends on implementation
    - HashSet → no insertion-order guarantee
    - LinkedHashSet → insertion order
    - TreeSet → sorted order

Map:
    - depends on implementation
    - HashMap → no ordering guarantee
    - LinkedHashMap → insertion order
    - TreeMap → sorted by keys

So remember:

        ORDER ≠ INDEX

A collection can maintain order without being index based.
================================================================================
*/


/*
================================================================================
3. BASIC COLLECTION STRUCTURE
================================================================================

Java Collection Framework roughly looks like:

                         Iterable
                            |
                       Collection
                     /     |       \
                  List     Set     Queue
                   |
             ---------------
             |             |
         ArrayList      LinkedList


Map is separate:

                         Map
                     /          \
                HashMap       TreeMap
                LinkedHashMap


IMPORTANT:

Map does NOT extend Collection.

Why?

Because Collection represents a group of individual elements:

    [10, 20, 30]

Map represents KEY-VALUE pairs:

    {101 = "Java"}
    {102 = "Python"}

So their abstraction is different.
================================================================================
*/


/*
================================================================================
4. LIST INTERFACE
================================================================================

List is an INTERFACE.

It represents an ordered collection.

Examples of List implementations:

    ArrayList
    LinkedList
    Vector
    Stack (legacy class extending Vector)

Hierarchy:

                    List
                     |
             ----------------
             |              |
         ArrayList       LinkedList


ArrayList and LinkedList are CLASSES.

List is an INTERFACE.

Example:

    List<Integer> list = new ArrayList<>();

Here:

    List       → reference type / interface
    ArrayList  → actual object / implementation


Similarly:

    List<Integer> list = new LinkedList<>();

Same interface, different implementation.
================================================================================
*/


/*
================================================================================
5. LOOSE COUPLING
================================================================================

This is an important reason for writing:

    List<Integer> list = new ArrayList<>();

instead of:

    ArrayList<Integer> list = new ArrayList<>();

WHY?

Because we program against the abstraction (List), not the implementation.

Example:

    List<Integer> list = new ArrayList<>();

Later:

    list = new LinkedList<>();

The variable type does not change.

Only implementation changes.

Diagram:

    List<Integer>
         |
         |
    ----------------
    |              |
ArrayList       LinkedList


This is called LOOSE COUPLING.

The code depends on the List contract rather than depending heavily
on ArrayList implementation.

Example:

    List<Integer> list = new ArrayList<>();

    list.add(10);
    list.add(20);
    list.remove(0);

These methods are available because List defines them.

If tomorrow:

    List<Integer> list = new LinkedList<>();

most List-based code can remain unchanged.

IMPORTANT:

    List<Integer> list = new ArrayList<>();

does NOT mean ArrayList becomes a List object.

The object is still:

    ArrayList object

The reference type is:

    List reference
================================================================================
*/


/*
================================================================================
6. COLLECTION INTERFACE
================================================================================

Collection is an interface in Java.

It represents a group of objects/elements.

Examples:

    List
    Set
    Queue

All of these extend Collection.

Simplified hierarchy:

                    Iterable
                       |
                  Collection
                 /     |      \
              List     Set    Queue


Collection provides common operations such as:

    add()
    remove()
    contains()
    size()
    isEmpty()
    clear()
    iterator()

But remember:

    Collection ≠ List

List provides additional List-specific operations such as:

    get(index)
    set(index, value)
    add(index, value)
    indexOf()

Therefore:

    Collection = common collection behavior

    List = ordered/index-oriented collection contract
================================================================================
*/


/*
================================================================================
7. ALL COLLECTIONS ARE NOT INDEX BASED
================================================================================

This is VERY IMPORTANT for understanding Iterator.

Many beginners think:

    Collection = index 0, 1, 2, 3...

That is WRONG.

Example:

ArrayList:

    index
      0    1    2    3
     [10] [20] [30] [40]

We can directly do:

    list.get(2)

LinkedList:

    10 → 20 → 30 → 40

There is no efficient direct jump to index 2.

To reach 30, traversal happens:

    head
     ↓
    10 → 20 → 30
          ↓
       index 2

Set:

    HashSet<Integer>

There is no:

    set.get(2)

because Set does not provide index-based access.

Therefore:

    Iterator becomes important.

Iterator provides a GENERAL way of traversing elements.

It does not require the collection to have indexes.
================================================================================
*/


/*
================================================================================
8. ITERABLE INTERFACE
================================================================================

Iterable is an interface.

Its important job:

    It makes an object capable of being ITERATED/TRAVERSED.

Conceptually:

                    Iterable<T>
                        |
                iterator() method
                        |
                        ↓
                  Iterator<T>


Simplified idea:

interface Iterable<T> {

    Iterator<T> iterator();

}


The iterator() method gives us an Iterator object.

Example:

    ArrayList<Integer> list = new ArrayList<>();

    Iterator<Integer> itr = list.iterator();

Now:

    list
      |
      | iterator()
      ↓
    Iterator
      |
      | hasNext()
      | next()
      ↓
    elements


This is the key relationship:

    Iterable → gives Iterator
    Iterator → traverses elements
================================================================================
*/


/*
================================================================================
9. ITERATOR INTERFACE
================================================================================

Iterator is also an interface.

Its job is:

    Traverse elements one by one.

Simplified:

interface Iterator<E> {

    boolean hasNext();

    E next();

    void remove();

    default void forEachRemaining(...);

}


The two most important methods are:

    hasNext()
    next()


Example:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {
        System.out.println(itr.next());
    }


How it works:

    hasNext()
         ↓
    "Is another element available?"
         |
       YES
         ↓
       next()
         ↓
    return next element
         |
         ↓
    move iterator position


================================================================================
*/


/*
================================================================================
10. ITERATOR DOES NOT MEAN "DATA STRUCTURE"
================================================================================

Very important distinction:

ArrayList = data structure / collection implementation

Iterator = traversal mechanism

Think:

    Collection
       |
       | contains data
       ↓
    [10, 20, 30, 40]

Iterator
       |
       | knows where it currently is
       ↓
    10 → 20 → 30 → 40


Iterator does not normally store a second copy of the entire collection.

It maintains traversal state.

For example:

    current position = 0

then:

    next() → element 0
    current position = 1

then:

    next() → element 1
    current position = 2

etc.
================================================================================
*/


/*
================================================================================
11. ARRAYLIST + ITERATOR
================================================================================

ArrayList implements Iterable.

Conceptually:

class ArrayList<E> implements List<E>, RandomAccess, Cloneable, Serializable {

    public Iterator<E> iterator() {
        return new ArrayListIterator();
    }

}


Then internally there can be an iterator implementation.

Conceptually:

class ArrayListIterator implements Iterator<E> {

    private int cursor = 0;

    public boolean hasNext() {
        return cursor < size;
    }

    public E next() {

        E element = elementData[cursor];

        cursor++;

        return element;
    }
}


IMPORTANT:

This is a simplified conceptual implementation.

Real JDK source has additional checks, fields and implementation details.


Visual structure:

    ArrayList
    -------------------------
    elementData
    -------------------------
    [10] [20] [30] [40]
     0    1    2    3

             |
             | iterator()
             ↓

    ArrayList Iterator
    -------------------------
    cursor = 0
    -------------------------


First:

    hasNext()

    cursor < size

    0 < 4
       ↓
      true


Then:

    next()

    elementData[0]

    returns 10

    cursor becomes 1


Next:

    hasNext()

    1 < 4
       ↓
      true

Then:

    next()

    elementData[1]

    returns 20

    cursor becomes 2


Eventually:

    cursor = 4

    hasNext()

    4 < 4
       ↓
      false
================================================================================
*/


/*
================================================================================
12. ARRAYLIST ITERATOR — STEP BY STEP
================================================================================

Suppose:

    ArrayList<Integer> list =
        [10, 20, 30];


Iterator:

    cursor = 0


STEP 1:

    hasNext()

    0 < 3 → true


STEP 2:

    next()

    elementData[0] → 10

    cursor = 1


STEP 3:

    hasNext()

    1 < 3 → true


STEP 4:

    next()

    elementData[1] → 20

    cursor = 2


STEP 5:

    hasNext()

    2 < 3 → true


STEP 6:

    next()

    elementData[2] → 30

    cursor = 3


STEP 7:

    hasNext()

    3 < 3 → false


So:

    while (itr.hasNext()) {
        System.out.println(itr.next());
    }

produces:

    10
    20
    30
================================================================================
*/


/*
================================================================================
13. WHY DOES ARRAYLIST ITERATOR USE A CURSOR?
================================================================================

Because ArrayList is backed by an array.

Conceptually:

    elementData
       ↓
    +----+----+----+----+
    | 10 | 20 | 30 | 40 |
    +----+----+----+----+
      0    1    2    3
           ↑
         cursor

The cursor tells the iterator:

    "Which element should I process next?"

Therefore ArrayList iterator can use:

    elementData[cursor]

This is one reason ArrayList traversal through Iterator is efficient.

Traversal:

    O(n)

Each next() is approximately O(1).
================================================================================
*/


/*
================================================================================
14. LINKEDLIST + ITERATOR
================================================================================

LinkedList has a completely different internal structure.

Conceptually:

    head
     |
     ↓
    [10 | next] → [20 | next] → [30 | null]


Node:

class Node {

    int data;

    Node next;
}


LinkedList:

class LinkedList {

    Node head;

}


Unlike ArrayList:

    LinkedList does not have an array like:

        elementData[0]

Instead, each node points to the next node.


So its iterator should NOT use:

    index++

Instead it can maintain:

    Node current


Conceptually:

class LinkedListIterator implements Iterator<Integer> {

    Node current = head;

    public boolean hasNext() {
        return current != null;
    }

    public Integer next() {

        int data = current.data;

        current = current.next;

        return data;
    }
}
================================================================================
*/


/*
================================================================================
15. LINKEDLIST ITERATOR — INTERNAL WORKING
================================================================================

Suppose:

    head
     |
     ↓
    [10] → [20] → [30] → null

Iterator:

    current = head


So:

    current
       ↓
    [10] → [20] → [30] → null


hasNext():

    current != null

    YES

    therefore true


next():

    int data = current.data;

    data = 10;


Then:

    current = current.next;


Now:

    current
       ↓
    [20] → [30] → null


Next next():

    data = 20

    current = current.next


Now:

    current
       ↓
    [30] → null


Next:

    data = 30

    current = current.next


Now:

    current = null


Then:

    hasNext()

    current != null

    false


Therefore traversal ends.
================================================================================
*/


/*
================================================================================
16. ARRAYLIST ITERATOR VS LINKEDLIST ITERATOR
================================================================================

ArrayList:

    Internal storage:
        array

    Iterator state:
        cursor/index

    next():

        elementData[cursor]

        cursor++


LinkedList:

    Internal storage:
        nodes

    Iterator state:
        current Node

    next():

        data = current.data
        current = current.next


Diagram:

ARRAYLIST:

    [10][20][30][40]
       ↑
     cursor


LINKEDLIST:

    [10] → [20] → [30] → null
      ↑
    current


Both expose the SAME Iterator contract:

    hasNext()
    next()

But their internal implementation is different.

THIS IS POLYMORPHISM.

Same interface:

    Iterator

Different implementations:

    ArrayList iterator
    LinkedList iterator
================================================================================
*/


/*
================================================================================
17. WHY ITERATOR IS POWERFUL
================================================================================

Suppose we want to traverse:

    ArrayList
    LinkedList
    HashSet
    TreeSet
    etc.

Their internal structures are different.

ArrayList:
    array

LinkedList:
    nodes

HashSet:
    hash table / buckets

TreeSet:
    tree

Yet we can write:

    Iterator<Integer> itr = collection.iterator();

    while (itr.hasNext()) {
        System.out.println(itr.next());
    }


We don't need to know the internal structure.

That is ABSTRACTION.

Iterator hides traversal implementation details.

We only care about its contract:

    hasNext()
    next()
================================================================================
*/


/*
================================================================================
18. SET AND HASHING — BUCKET IDEA
================================================================================

HashSet is commonly implemented using hash-table based structures.

Conceptually:

             Hash function
                  |
                  ↓
              hashCode
                  |
                  ↓
             bucket index
                  |
       -----------------------
       |    |    |    |     |
      B0   B1   B2   B3    B4
            |
            ↓
        elements


For example:

    element.hashCode()
            ↓
       hash calculation
            ↓
       bucket location


Modern HashMap/HashSet implementations use more sophisticated internal
structures and collision handling, including treeification under certain
conditions.

IMPORTANT:

Don't memorize:

    "HashSet is simply an array."

Instead remember:

    HashSet is hash-table based.

Iterator abstracts away these bucket details.

You don't manually traverse buckets.

You simply do:

    Iterator<Integer> itr = set.iterator();

    while (itr.hasNext()) {
        System.out.println(itr.next());
    }
================================================================================
*/


/*
================================================================================
19. TREESET / TREEMAP
================================================================================

TreeSet and TreeMap are tree-based.

Conceptually:

             50
            /  \
          30    70
         / \    / \
       20  40  60  80


TreeSet stores elements according to sorted ordering.

TreeMap stores key-value mappings according to sorted keys.

Modern Java implementations use Red-Black trees.

You don't need to know tree nodes to use Iterator.

Again:

    internal structure
           ↓
        hidden
           ↓
       Iterator
           ↓
     common traversal


This is abstraction.
================================================================================
*/


/*
================================================================================
20. QUEUE
================================================================================

Queue is another Collection interface.

Typical concept:

    FIFO

    First In → First Out

Example:

    [10] [20] [30]

remove:

    10 comes out first.


IMPORTANT CORRECTION:

Do NOT memorize:

    "Queue uses ArrayList."

Queue is an INTERFACE.

Different Queue implementations exist.

Examples:

    LinkedList
    ArrayDeque
    PriorityQueue
    etc.

Their internal structures differ.

Iterator provides a common traversal mechanism where supported.
================================================================================
*/


/*
================================================================================
21. ENHANCED FOR LOOP
================================================================================

Syntax:

    for (Integer x : list) {
        System.out.println(x);
    }


This is called:

    Enhanced for loop
    or
    for-each loop


But internally, for an Iterable object, it is conceptually based on Iterator.

Suppose:

    List<Integer> list = new ArrayList<>();

    for (Integer x : list) {
        System.out.println(x);
    }


Conceptually similar to:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {

        Integer x = itr.next();

        System.out.println(x);
    }


So:

    enhanced for loop
           ↓
       Iterable
           ↓
       iterator()
           ↓
       Iterator
           ↓
    hasNext() + next()


This is one of the MOST IMPORTANT connections.
================================================================================
*/


/*
================================================================================
22. WHY ENHANCED FOR LOOP WORKS WITHOUT INDEX
================================================================================

Consider:

    HashSet<Integer> set = new HashSet<>();

There is no:

    set.get(0)

So how can this work?

    for (Integer x : set) {
        System.out.println(x);
    }


Because it does NOT depend on indexes.

It obtains an Iterator.

Conceptually:

    Iterator<Integer> itr = set.iterator();

    while (itr.hasNext()) {

        Integer x = itr.next();

    }


This is why enhanced for-loop works with many collections that are
not index based.
================================================================================
*/


/*
================================================================================
23. ITERABLE VS ITERATOR
================================================================================

This confusion is extremely common.

ITERABLE:

    "I can provide something that can iterate over me."

ITERATOR:

    "I am the object that performs the iteration."


Think:

    Iterable = BOOK
    Iterator = FINGER MOVING THROUGH THE BOOK


Or:

    Iterable = classroom containing students
    Iterator = person walking through students one by one


Technically:

    Iterable has:

        iterator()


Iterator has:

        hasNext()
        next()
        remove()
        forEachRemaining()


Relationship:

    Iterable
       |
       | iterator()
       ↓
    Iterator
       |
       | next()
       ↓
    element
================================================================================
*/


/*
================================================================================
24. IMPORTANT: Iterable DOES NOT "HAVE ITERATOR METHOD" IN COLLECTION
================================================================================

Precise hierarchy:

    Iterable
       |
       ↓
    Collection
       |
       ↓
    List
       |
       ↓
    ArrayList


The iterator() method is declared in:

    Iterable

Collection inherits it.

List inherits it through Collection.

ArrayList gets it through the hierarchy and provides its implementation.

So:

    ArrayList → implements List
    List → extends Collection
    Collection → extends Iterable

Therefore:

    ArrayList is indirectly an Iterable.


Similarly:

    LinkedList → List → Collection → Iterable
================================================================================
*/


/*
================================================================================
25. ITERATOR METHODS
================================================================================

Iterator has four important methods to know:

    1. hasNext()
    2. next()
    3. remove()
    4. forEachRemaining()


Let's understand each.
================================================================================
*/


/*
================================================================================
26. hasNext()
================================================================================

Purpose:

    Checks whether another element is available.

Return type:

    boolean


Example:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {

        System.out.println(itr.next());

    }


Conceptually:

    current position
          |
          ↓
    [10][20][30]
          ↑

    Is there an element at/after current position?

        YES → true
        NO  → false


IMPORTANT:

hasNext() does NOT move the iterator.

It only checks.

    hasNext() → check

    next()    → move + return
================================================================================
*/


/*
================================================================================
27. next()
================================================================================

Purpose:

    Returns the next element and advances the iterator.

Example:

    Iterator<Integer> itr = list.iterator();

    itr.next();


If:

    [10][20][30]
      ↑
    cursor

then:

    next() → 10

cursor moves:

    [10][20][30]
          ↑
        cursor


Calling next() again:

    → 20


Important:

next() should generally be called only after checking:

    hasNext()


If there is no next element, next() throws:

    NoSuchElementException
================================================================================
*/


/*
================================================================================
28. remove()
================================================================================

Iterator also has:

    remove()


It removes the last element returned by next().

Example:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {

        Integer x = itr.next();

        if (x == 20) {
            itr.remove();
        }
    }


Suppose:

    [10, 20, 30]

next() → 10
next() → 20

then:

    remove()

Result:

    [10, 30]


IMPORTANT:

remove() is an OPTIONAL OPERATION.

An Iterator implementation is allowed to not support it.

If unsupported:

    UnsupportedOperationException

can be thrown.


Also:

    remove() cannot normally be called arbitrarily.

It is tied to the most recent next() call.
================================================================================
*/


/*
================================================================================
29. WHY DID WE NOT IMPLEMENT remove() IN OUR SIMPLE ITERATOR?
================================================================================

Suppose we wrote:

class MyIterator implements Iterator<Integer> {

    public boolean hasNext() {
        ...
    }

    public Integer next() {
        ...
    }
}


You may ask:

    Iterator has remove().
    Why didn't we implement it?


Because in modern Java, Iterator's remove() is a DEFAULT method.

Conceptually:

interface Iterator<E> {

    boolean hasNext();

    E next();

    default void remove() {
        throw new UnsupportedOperationException(
            "remove"
        );
    }
}


Therefore implementing classes don't HAVE TO override it.

If they need custom remove behavior, they can override it.

Otherwise the default behavior remains.

This is why our simple iterator only needed:

    hasNext()
    next()


IMPORTANT:

This is different from an abstract method.

Abstract method:
    implementing class MUST provide implementation.

Default method:
    implementing class may use inherited default implementation.
================================================================================
*/


/*
================================================================================
30. forEachRemaining()
================================================================================

Iterator also provides:

    forEachRemaining(...)


Purpose:

    Perform an action for every remaining element.

Example:

    Iterator<Integer> itr = list.iterator();

    itr.forEachRemaining(
        x -> System.out.println(x)
    );


Suppose:

    [10][20][30][40]

If iterator has already consumed:

    10
    20

then:

    forEachRemaining(...)

processes:

    30
    40


It means:

    "Whatever is left from the current iterator position,
     perform the given action on each remaining element."


We don't need to go deep into lambda here.

Basic idea is enough:

    Iterator
        |
        ↓
    forEachRemaining()
        |
        ↓
    process all remaining elements
================================================================================
*/


/*
================================================================================
31. WHY DOES ITERATOR NOT HAVE add()?
================================================================================

Very important conceptual question.

You might ask:

    Iterator has remove()

but:

    Why doesn't Iterator have add()?


Because Iterator's primary responsibility is:

    TRAVERSAL

It is designed to move through an existing collection.

Its basic operations are:

    check next element
    get next element
    optionally remove current element


Adding an element is more complicated because different collections have
different insertion rules.

Example:

ArrayList:

    can add at end or index.

LinkedList:

    can add nodes.

Set:

    duplicate restrictions.

Sorted Set:

    insertion position is determined by ordering.

Queue:

    insertion follows queue semantics.

Map:

    insertion means key-value association and Map isn't an Iterator-based
    Collection in the same hierarchy.


Therefore insertion belongs to the collection's API rather than the
generic Iterator contract.

List has:

    add()

Collection has:

    add()

Iterator has:

    no add()


This keeps responsibilities separated.

Iterator:

    "Traverse/remove during traversal."

Collection:

    "Manage the collection."
================================================================================
*/


/*
================================================================================
32. SINGLE RESPONSIBILITY IDEA
================================================================================

Think of responsibilities:

Collection:

    add
    remove
    clear
    contains
    size
    etc.


Iterator:

    traverse
    check next
    optionally remove


So:

    Collection → manages data

    Iterator → manages traversal state


This separation is a major design reason.
================================================================================
*/


/*
================================================================================
33. CONCURRENTMODIFICATIONEXCEPTION
================================================================================

Now we reach a VERY IMPORTANT topic.

Suppose:

    List<Integer> list =
        new ArrayList<>();

    list.add(10);
    list.add(20);
    list.add(30);


Then:

    for (Integer x : list) {

        if (x == 20) {
            list.remove(x);
        }
    }


This can cause:

    ConcurrentModificationException


Why?

Because an Iterator is traversing the collection while the collection
is structurally modified outside the iterator.


Conceptually:

    Iterator
       |
       ↓
    "I am traversing this structure."

Meanwhile:

    list.remove(...)
       |
       ↓
    structure changed!


Iterator detects that the collection changed unexpectedly.

This is called:

    fail-fast behavior


================================================================================
*/


/*
================================================================================
34. HOW DOES ARRAYLIST DETECT MODIFICATION?
================================================================================

Conceptually, ArrayList maintains:

    modCount

This represents the number of structural modifications.

Iterator can maintain:

    expectedModCount


Initially:

    ArrayList.modCount = 5

Iterator:

    expectedModCount = 5


During traversal:

    expectedModCount == modCount

Everything okay.


Suppose external code does:

    list.add(50);


Now:

    modCount = 6

but iterator still has:

    expectedModCount = 5


Iterator checks:

    expectedModCount != modCount

    5 != 6

       ↓
    modification detected

       ↓
ConcurrentModificationException
================================================================================
*/


/*
================================================================================
35. WHY DOES iterator.remove() WORK DIFFERENTLY?
================================================================================

This is a beautiful point.

Suppose:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {

        Integer x = itr.next();

        if (x == 20) {
            itr.remove();
        }
    }


Why is this allowed?

Because the iterator itself performs the removal.

The iterator knows that the collection is being modified.

It can update its internal state accordingly.

Conceptually:

    iterator.remove()
          |
          ↓
    collection modified
          |
          ↓
    iterator updates expected state


Whereas:

    list.remove(...)
          |
          ↓
    modification happens outside iterator
          |
          ↓
    iterator detects unexpected change
================================================================================
*/


/*
================================================================================
36. "CONCURRENT" DOES NOT NECESSARILY MEAN MULTITHREADING HERE
================================================================================

ConcurrentModificationException's name can be misleading.

It does NOT necessarily mean:

    two threads are running.

You can get it in a SINGLE THREAD.

Example:

    for (Integer x : list) {
        list.remove(x);
    }


Only one thread may exist.

The actual issue is:

    collection was structurally modified while an iterator was
    active, in an unsupported/unexpected way.


"Concurrent" here means modification occurring during iteration.
================================================================================
*/


/*
================================================================================
37. STRUCTURAL MODIFICATION
================================================================================

Structural modification generally means changing the structure/size
of the collection.

Examples:

    add()
    remove()
    clear()


For ArrayList, these can affect its structure.

But not every change necessarily counts as structural.

Example:

    list.set(0, 100);


This changes an existing element rather than changing the size.

Therefore it is generally not considered a structural modification
for ArrayList's fail-fast mechanism.


Remember:

    structural change ≈ change affecting collection structure/size

Exact behavior depends on the collection implementation.
================================================================================
*/


/*
================================================================================
38. FAIL-FAST IS NOT A THREAD-SAFETY GUARANTEE
================================================================================

Very important.

Fail-fast behavior is designed to detect many unexpected modifications.

But you should NOT depend on ConcurrentModificationException for
correct program logic.

It is a bug-detection mechanism, not a synchronization mechanism.

Also, fail-fast behavior is generally best-effort.

It does NOT mean:

    "Java guarantees that every concurrent modification will always
     throw this exception."


Therefore:

    Don't use ConcurrentModificationException as a concurrency strategy.
================================================================================
*/


/*
================================================================================
39. WHY DOES ARRAYLIST IMPLEMENT ITERABLE, NOT ITERATOR?
================================================================================

This is one of the BEST conceptual questions.

You asked:

    Why not:

        class ArrayList implements Iterator

    and directly implement:

        hasNext()
        next()


Instead Java does:

        ArrayList implements Iterable

        ArrayList.iterator()
                  ↓
        returns Iterator


There are several reasons.
================================================================================
*/


/*
================================================================================
40. REASON #1 — SEPARATION OF CONCERNS
================================================================================

ArrayList's job:

    STORE AND MANAGE DATA


Iterator's job:

    TRAVERSE DATA


If ArrayList itself were the Iterator:

    ArrayList would need to maintain:

        data
        cursor
        iteration state


Now one object would have two responsibilities:

    Collection management
          +
    Traversal state


This mixes responsibilities.


Current design:

    ArrayList
    -------------------
    data
    size
    modifications
    etc.
    -------------------

           |
           | iterator()
           ↓

    ArrayList Iterator
    -------------------
    cursor
    expectedModCount
    traversal state
    -------------------


Much cleaner.


This follows the general software-design principle:

    Separation of Concerns.
================================================================================
*/


/*
================================================================================
41. REASON #2 — MULTIPLE ITERATORS
================================================================================

THIS IS EXTREMELY IMPORTANT.

Suppose ArrayList itself were Iterator.

Then:

    ArrayList list = ...;

would have ONE cursor.

Now imagine:

    Iterator<Integer> itr1 = list.iterator();
    Iterator<Integer> itr2 = list.iterator();


With Java's actual design:

    itr1 → cursor = 0
    itr2 → cursor = 0


They have independent traversal states.

Example:

    list = [10, 20, 30]


itr1.next()
    ↓
    10

itr1 cursor:
    1


itr2.next()
    ↓
    10

itr2 cursor:
    1


They can traverse independently.


Diagram:

                    ArrayList
               [10][20][30]
                 ↑
                 |
              iterator()
               /      \
              /        \
             ↓          ↓
           itr1        itr2
        cursor=0      cursor=0


Now:

    itr1.next() → 10

    itr1 cursor = 1


But:

    itr2 cursor = 0


So:

    itr2.next() → 10


Independent state!
================================================================================
*/


/*
================================================================================
42. NESTED LOOP PROBLEM
================================================================================

Now imagine the collection itself were the iterator.

Example:

    for (Integer a : list) {

        for (Integer b : list) {

            ...
        }
    }


We need TWO independent traversal states.

Actual Java design:

    outer iterator
         ↓
       cursor 0

    inner iterator
         ↓
       cursor 0


They don't interfere.


Diagram:

    ArrayList
       |
       +--------> Iterator 1
       |             cursor = 1
       |
       +--------> Iterator 2
                     cursor = 2


If ArrayList itself had only one iterator state:

    ArrayList cursor = ?


Then outer loop changes cursor.

Inner loop changes the same cursor.

They would interfere with each other.

Therefore:

    iterator state belongs to the Iterator object,

not the collection itself.
================================================================================
*/


/*
================================================================================
43. MULTIPLE ITERATORS ARE THE KEY
================================================================================

One collection can create many iterator objects:

    list.iterator()
          ↓
        itr1

    list.iterator()
          ↓
        itr2

    list.iterator()
          ↓
        itr3


Each iterator can have independent state.

    itr1 → cursor 0
    itr2 → cursor 2
    itr3 → cursor 1


Same collection.

Different traversal positions.

This would be difficult/incorrect if the collection itself had to be
the iterator.
================================================================================
*/


/*
================================================================================
44. REASON #3 — ITERATION STRATEGY CAN DIFFER
================================================================================

A collection can potentially provide different ways of traversal.

For example, a data structure could provide:

    normal iterator
    reverse iterator
    special traversal iterator

The collection remains the data structure.

The iterator represents traversal behavior/state.

This makes the design extensible.
================================================================================
*/


/*
================================================================================
45. REASON #4 — SAME COLLECTION, DIFFERENT ITERATOR OBJECTS
================================================================================

Think of:

    ArrayList
        |
        +---- Iterator A
        |
        +---- Iterator B
        |
        +---- Iterator C


All are looking at the same collection.

But:

    A has its own position.
    B has its own position.
    C has its own position.


Therefore:

    Collection = shared data

    Iterator = individual traversal session
================================================================================
*/


/*
================================================================================
46. THE COMPLETE INTERNAL DESIGN
================================================================================

Simplified conceptual hierarchy:

                    Iterable<E>
                        |
                        | iterator()
                        ↓
                    Iterator<E>
                    /    |     \
                   /     |      \
              hasNext() next() remove()
                         |
                         |
                 -------------------
                 |                 |
                 ↓                 ↓
      ArrayListIterator    LinkedListIterator


ArrayList:

    class ArrayList<E> implements Iterable<E> {

        public Iterator<E> iterator() {
            return new ArrayListIterator();
        }
    }


ArrayList Iterator:

    class ArrayListIterator<E> implements Iterator<E> {

        int cursor = 0;

        public boolean hasNext() {
            return cursor < size;
        }

        public E next() {
            E element = elementData[cursor];
            cursor++;
            return element;
        }
    }


LinkedList:

    class LinkedList<E> implements Iterable<E> {

        Node head;

        public Iterator<E> iterator() {
            return new LinkedListIterator(head);
        }
    }


LinkedList Iterator:

    class LinkedListIterator<E> implements Iterator<E> {

        Node current;

        LinkedListIterator(Node head) {
            current = head;
        }

        public boolean hasNext() {
            return current != null;
        }

        public E next() {

            E data = current.data;

            current = current.next;

            return data;
        }
    }


IMPORTANT:

This is a conceptual model to understand the architecture,
not a copy of the exact OpenJDK source code.
================================================================================
*/


/*
================================================================================
47. COMPLETE FLOW
================================================================================

When we write:

    List<Integer> list = new ArrayList<>();

    Iterator<Integer> itr = list.iterator();


What happens conceptually?

STEP 1:

    list is a reference of type List.

STEP 2:

    actual object = ArrayList.

STEP 3:

    list.iterator()

    dynamically reaches ArrayList's iterator() implementation.

STEP 4:

    ArrayList creates/returns an ArrayList Iterator object.

STEP 5:

    Iterator reference stores that object.

STEP 6:

    itr.hasNext()

    calls ArrayList iterator's hasNext().

STEP 7:

    itr.next()

    calls ArrayList iterator's next().

This is runtime polymorphism.
================================================================================
*/


/*
================================================================================
48. WHY DOES LINKEDLIST ALSO USE ITERATOR?
================================================================================

Because clients should not need to know:

    "Is this ArrayList?"

or:

    "Is this LinkedList?"


They can simply write:

    Iterator<Integer> itr = collection.iterator();

    while (itr.hasNext()) {
        System.out.println(itr.next());
    }


The code works through the Iterator contract.

Internally:

    ArrayList
       ↓
    ArrayListIterator


LinkedList
       ↓
    LinkedListIterator


HashSet
       ↓
    HashSet-specific iterator


TreeSet
       ↓
    TreeSet-specific iterator


Different internal implementations.

Same public Iterator contract.
================================================================================
*/


/*
================================================================================
49. ITERATOR = ABSTRACTION + POLYMORPHISM
================================================================================

ITERATOR demonstrates both:

    ABSTRACTION

and

    POLYMORPHISM


Abstraction:

    We don't care how traversal is implemented.

We only know:

    hasNext()
    next()


Polymorphism:

    Iterator reference can point to different iterator implementations.

Example:

    Iterator<Integer> itr;

    itr = arrayList.iterator();

or:

    itr = linkedList.iterator();

or:

    itr = hashSet.iterator();


Same reference type:

    Iterator

Different actual object.
================================================================================
*/


/*
================================================================================
50. ITERABLE + ITERATOR IN ONE DIAGRAM
================================================================================

                       Iterable<E>
                            |
                            |
                     iterator()
                            |
                            ↓
                     Iterator<E>
                     /     |      \
                    /      |       \
             hasNext()   next()   remove()
                            |
                            ↓
                       next element


Collection hierarchy:

                       Iterable
                           |
                       Collection
                  /        |        \
                List      Set      Queue
                 |
           --------------
           |            |
       ArrayList     LinkedList


ArrayList:

    iterator()
       ↓
    ArrayListIterator
       ↓
    cursor


LinkedList:

    iterator()
       ↓
    LinkedListIterator
       ↓
    current Node


HashSet:

    iterator()
       ↓
    Hash-based traversal


TreeSet:

    iterator()
       ↓
    tree-based traversal
================================================================================
*/


/*
================================================================================
51. IMPORTANT CORRECTION ABOUT ORDER
================================================================================

Do not memorize this:

    Ordered:
        ArrayList
        LinkedList

    Unordered:
        Set
        Map

as an absolute rule.

Better classification:

    ArrayList
        insertion order maintained

    LinkedList
        insertion order maintained

    HashSet
        no guaranteed iteration order

    LinkedHashSet
        insertion order maintained

    TreeSet
        sorted order

    HashMap
        no guaranteed iteration order

    LinkedHashMap
        insertion order

    TreeMap
        sorted by keys


So "Set" and "Map" are categories/interfaces whose implementations
can have different ordering characteristics.
================================================================================
*/


/*
================================================================================
52. RANDOM ACCESS VS SEQUENTIAL ACCESS
================================================================================

ArrayList:

    list.get(3)

Can directly access the underlying array position.

Average/random access:

    O(1)


LinkedList:

    list.get(3)

Must traverse nodes to reach the requested position.

Typical access:

    O(n)


BUT:

Iterator traversal for both:

    O(n) total for traversing all elements.


ArrayList:

    next() ≈ O(1)

LinkedList:

    next() ≈ O(1)

because the iterator already maintains the next location.

This is an IMPORTANT distinction.


LinkedList:

    get(i) repeatedly in a loop:

        for (int i = 0; i < n; i++) {
            list.get(i);
        }

can become O(n²).


But:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {
        itr.next();
    }

is O(n).

Why?

Because iterator follows:

    current → current.next

rather than repeatedly starting from head to find index i.
================================================================================
*/


/*
================================================================================
53. ITERATOR VS get(i)
================================================================================

ArrayList:

    for (int i = 0; i < list.size(); i++) {
        list.get(i);
    }

    approximately O(n)

LinkedList:

    for (int i = 0; i < list.size(); i++) {
        list.get(i);
    }

    can be O(n²)


Iterator:

    Iterator<Integer> itr = list.iterator();

    while (itr.hasNext()) {
        itr.next();
    }

    O(n) traversal


Therefore Iterator gives us a collection-independent traversal mechanism.
================================================================================
*/


/*
================================================================================
54. WHY "ALL COLLECTIONS ARE NOT INDEX BASED" MATTERS
================================================================================

Suppose:

    ArrayList:

        get(0)
        get(1)
        get(2)


But:

    HashSet:

        get(0)  ❌
        get(1)  ❌


Then how can we process every element?

Iterator:

    Iterator<Integer> itr = set.iterator();

    while (itr.hasNext()) {
        Integer value = itr.next();
    }


Therefore:

    Iterator does not depend on index.

This is one of the biggest reasons Iterator exists.
================================================================================
*/


/*
================================================================================
55. QUICK DIFFERENCE
================================================================================

Collection:

    Represents a group of elements.

Iterable:

    Represents something that can provide an Iterator.

Iterator:

    Traverses the elements.

List:

    Ordered Collection interface.

ArrayList:

    List implementation backed by a resizable array.

LinkedList:

    List implementation based on linked nodes.

Enhanced for loop:

    Convenient syntax that uses Iterator for Iterable collections.
================================================================================
*/


/*
================================================================================
56. MOST IMPORTANT INTERVIEW QUESTIONS
================================================================================

Q1. What is Iterator?

Answer:

    Iterator is an interface used to traverse elements of a collection
    one by one without exposing the collection's internal structure.


Q2. What is Iterable?

Answer:

    Iterable is an interface whose iterator() method provides an Iterator
    for traversing its elements.


Q3. Difference?

    Iterable → provides Iterator

    Iterator → performs traversal


Q4. Why Iterator?

    Because not every collection is index based.


Q5. Does LinkedList have random access?

    No, not efficient random access.


Q6. Does ArrayList maintain insertion order?

    Yes.


Q7. Is ArrayList a class or interface?

    Class.


Q8. Is List a class or interface?

    Interface.


Q9. Is LinkedList a class or interface?

    Class.


Q10. Why:

        List<Integer> list = new ArrayList<>();

    instead of:

        ArrayList<Integer> list = new ArrayList<>();

    Answer:

        Programming to the interface provides loose coupling and allows
        the implementation to be changed more easily.


Q11. Why does ArrayList implement Iterable instead of Iterator?

    Because collection data and traversal state are separate concerns.

    Multiple independent Iterator objects can traverse the same collection
    independently.


Q12. Why can enhanced for-loop work with HashSet?

    Because it uses Iterator rather than index access.


Q13. What happens if next() is called when no element remains?

    NoSuchElementException.


Q14. Why didn't our iterator implement remove()?

    Because Iterator's remove() has a default implementation that can
    throw UnsupportedOperationException.


Q15. Why no add() in Iterator?

    Iterator focuses on traversal and optional removal. Collection
    modification/insertion belongs to the collection API.


Q16. What is ConcurrentModificationException?

    A fail-fast exception that may occur when a collection is structurally
    modified unexpectedly while it is being iterated.


Q17. Can ConcurrentModificationException happen in one thread?

    Yes.


Q18. Does it guarantee thread safety?

    No.


Q19. Why is iterator.remove() special?

    Because the iterator performs the removal and can maintain its
    traversal state consistently.


Q20. Why are multiple iterators important?

    Each iterator maintains independent traversal state, enabling nested
    loops and independent traversals.
================================================================================
*/


/*
================================================================================
57. FINAL MEMORY TRICK
================================================================================

Remember this sentence:

    "Iterable gives, Iterator moves."

Meaning:

    Iterable
        ↓
    gives iterator()

    Iterator
        ↓
    moves through elements using next()


And:

    hasNext() → CHECK

    next() → GET + MOVE

    remove() → REMOVE LAST RETURNED ELEMENT

    forEachRemaining() → PROCESS WHAT IS LEFT


And:

    Collection → DATA

    Iterator → TRAVERSAL STATE


And:

    ArrayList Iterator → CURSOR

    LinkedList Iterator → CURRENT NODE


And:

    ArrayList → array → random access

    LinkedList → nodes → sequential traversal


And finally:

    Collection
         |
         ↓
      Iterable
         |
     iterator()
         |
         ↓
      Iterator
       /    \
    hasNext next
================================================================================
*/


/*
================================================================================
58. ONE FINAL MASTER DIAGRAM
================================================================================


                         JAVA COLLECTION WORLD
                                  |
                    +-------------+-------------+
                    |                           |
              Collection                       Map
                    |                           |
          +---------+---------+          HashMap / TreeMap /
          |         |         |          LinkedHashMap
         List      Set      Queue
          |
      +---+---+
      |       |
 ArrayList LinkedList
      |       |
      |       |
      +---+---+
          |
       Iterable
          |
      iterator()
          |
          ↓
       Iterator
          |
    +-----+------+----------------+

 hasNext()     next()          remove()
                                   |
                          optional operation

                       |
                       ↓
                remaining elements


ArrayList:

    [10][20][30][40]
       ↑
     cursor


LinkedList:

    [10] → [20] → [30] → null
      ↑
    current

    for (Integer x : collection)

                ↓

          collection.iterator()

                ↓

             hasNext()

               next()

                ↓

             element

    Collection changes unexpectedly

    ConcurrentModificationException

MOST IMPORTANT DESIGN IDEA:

    ✓ collection-independent traversal

================================================================================
