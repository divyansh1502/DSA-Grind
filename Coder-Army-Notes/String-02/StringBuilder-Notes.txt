/*
===========================================================
1. WHAT IS A STRING?
===========================================================

String is a sequence of characters.

Example:
*/

String name = "Divyansh";


// String is a class in Java:
String s = new String("Hello");


/*
IMPORTANT:

String is NOT a primitive data type.

It is a class present in:
java.lang.String

Java automatically imports java.lang.*


Example:
*/

String city = "Lucknow";


/*
===========================================================
2. STRING IMMUTABILITY
===========================================================

String objects are IMMUTABLE.

Immutable means:
Once a String object is created, its actual content
cannot be changed.

Example:
*/

String s1 = "Hello";

s1.concat(" World");

System.out.println(s1);

// Output:
// Hello


/*
Why?

concat() creates a NEW String object.

The original "Hello" remains unchanged.


If we want to store the new String:
*/

String s2 = "Hello";

s2 = s2.concat(" World");

System.out.println(s2);

// Output:
// Hello World


/*
===========================================================
3. STRING POOL
===========================================================

Java maintains a special memory area called:

String Constant Pool (SCP)

String literals are generally stored in the String Pool.

Example:
*/

String a = "Hello";
String b = "Hello";


/*
Both can refer to the same String object in the
String Constant Pool.

Therefore:
*/

System.out.println(a == b);

// Output:
// true


/*
But when using new:

*/

String c = new String("Hello");
String d = new String("Hello");


/*
Two different objects are created in Heap memory.

Therefore:
*/

System.out.println(c == d);

// Output:
// false


/*
To compare String CONTENT, use equals():

*/

System.out.println(c.equals(d));

// Output:
// true

6. charAt()
===========================================================

Returns the character at a particular index.

Index starts from 0.
*/

// Output:
// J
// v


/*
===========================================================
7. substring()
===========================================================

Used to extract a portion of a String.

substring(beginIndex)

substring(beginIndex, endIndex)

IMPORTANT:
endIndex is EXCLUSIVE.
*/

String str = "Hello World";

System.out.println(str.substring(6));

// World

System.out.println(str.substring(0, 5));

// Hello


/*
===========================================================
8. concat()
===========================================================

Joins two Strings.
*/

String first = "Hello";

String result = first.concat(second);

System.out.println(result);

// Hello World


/*
IMPORTANT:
String is immutable, so concat() does not modify
the original String.
*/

===========================================================
10. equalsIgnoreCase()
===========================================================

/*
===========================================================
11. compareTo()
===========================================================

Compares two Strings lexicographically.

Returns:

0  -> both Strings are equal
positive -> first String is greater
negative -> first String is smaller
*/

System.out.println(a.compareTo(b));

// Negative value

===========================================================
12. compareToIgnoreCase()
===========================================================

Same as compareTo(), but ignores case.
*/

===========================================================
                 STRINGBUFFER
===========================================================

StringBuffer is a mutable sequence of characters.

Unlike String:

String       -> Immutable
StringBuffer -> Mutable


Package:
java.lang.StringBuffer
===========================================================
*/


/*
Example:
*/

StringBuffer sb = new StringBuffer("Hello");

sb.append(" World");

System.out.println(sb);

// Hello World


/*
Here the SAME StringBuffer object is modified.

No new String object is required for every modification.
*/

/*
===========================================================
37. STRINGBUFFER vs STRINGBUILDER
===========================================================

StringBuffer and StringBuilder are MUTABLE.

Both are used when we need frequent modifications
to character sequences.


MAIN DIFFERENCE:

StringBuffer:
-> Thread-safe
-> Methods are synchronized
-> Slightly slower
-> Suitable for multiple-thread environments

StringBuilder:
-> Not thread-safe
-> Methods are not synchronized
-> Faster
-> Suitable for single-threaded environments
===========================================================
*/


/*
===========================================================
38. STRING vs STRINGBUFFER vs STRINGBUILDER
===========================================================
*/

/*

+------------------+-------------+----------------+----------------+
| Feature          | String      | StringBuffer   | StringBuilder  |
+------------------+-------------+----------------+----------------+
| Mutable?         | No          | Yes            | Yes            |
| Modification     | New object  | Same object    | Same object    |
| Thread Safe?     | Immutable   | Yes            | No             |
| Synchronized?    | N/A         | Yes            | No             |
| Performance      | Slower for  | Slower than    | Faster         |
|                  | many edits  | Builder        |                |
| Introduced       | Java 1.0    | Java 1.0      | Java 5         |
| Best Use         | Fixed text  | Multi-thread   | Single-thread  |
+------------------+-------------+----------------+----------------+

*/


/*
===========================================================
39. WHEN TO USE WHAT?
===========================================================

USE STRING WHEN:

-> Text does not change frequently.
-> You need immutable data.
-> You are storing names, messages, URLs etc.

Example:
*/

String name = "Divyansh";


/*
USE STRINGBUFFER WHEN:

-> String content changes frequently.
-> Multiple threads may access/modify the same object.
-> Thread safety is required.
*/

StringBuffer buffer = new StringBuffer("Hello");


/*
USE STRINGBUILDER WHEN:

-> String content changes frequently.
-> Only one thread is working with the object.
-> Performance is important.
*/

StringBuilder builder = new StringBuilder("Hello");


/*
===========================================================
40. WHY STRINGBUILDER IS FASTER THAN STRING?
===========================================================

Consider:

*/

String str = "A";

str = str + "B";
str = str + "C";
str = str + "D";


/*
Because String is immutable, every modification may
create a new String object.

Conceptually:

"A"
"AB"
"ABC"
"ABCD"


This creates unnecessary objects.

Instead:

*/

StringBuilder sb = new StringBuilder("A");

sb.append("B");
sb.append("C");
sb.append("D");


/*
The same mutable object can be modified.

Therefore StringBuilder is generally better for
repeated String modifications.
*/

--------------------------------------------

StringBuilder:
*/

*/


/*
===========================================================
42. COMMON INTERVIEW QUESTION
===========================================================

Q: Difference between == and equals() for String?

==

Checks whether two references point to the same object.

equals()

Checks whether two Strings have the same content.

Example:
*/

String a = new String("Java");
String b = new String("Java");

System.out.println(a == b);

// false

System.out.println(a.equals(b));

// true


/*
===========================================================
43. IMPORTANT MEMORY CONCEPT
===========================================================

String literals:

*/

String a = "Java";
String b = "Java";


/*
Usually both refer to the same pooled String object.

          STRING POOL

              "Java"
              /    \
             /      \
            a        b


Therefore:
*/

a == b

// true


/*
Using new:

*/

String c = new String("Java");
String d = new String("Java");


/*

             HEAP

          "Java"       "Java"
             ↑             ↑
             c             d

c == d -> false

c.equals(d) -> true
*/
